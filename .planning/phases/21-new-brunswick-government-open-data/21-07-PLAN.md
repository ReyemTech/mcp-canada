<objective>
Close the phase: prove the 22 tools work against the real portals, make the catalogue and the
project's own documentation tell the truth, and give the phase traceable requirement IDs.

Three things make this plan more than bookkeeping.

**The live-integration mandate.** CONTEXT.md is explicit that integration tests MUST hit
`geonb.snb.ca` and `open.canada.ca` and assert field presence and non-null values, not just response
shape. That mandate exists because mocked tests missed a live HTTP 400 in Manitoba and a
wrong-layer bug in Saskatchewan, and because a tolerated upstream error hid dead Toronto TTC tools
for months. `tests/test_integration_test_quality.py` enforces the banned masking idioms in the
default unit suite, so a test written the lazy way fails the build.

**The documentation correction.** CLAUDE.md's Socrata section carries a forward-looking reuse note
that names New Brunswick. Plan-time live probing found that note is right about NB for the wrong
reason — `gnb.socrata.com` really is a live keyless Socrata portal serving 312 NB datasets — while
21-CONTEXT.md's claim that no NB Socrata instance exists is wrong. This plan writes the verified
facts, not either prior guess.

**Requirement traceability.** Phase 21 entered planning with `Requirements: TBD`. NB-01..NB-25 land
in REQUIREMENTS.md here, matching what phases 17 through 20 each did.

Purpose: ship a phase that is provably working, accurately documented and traceable.
Output: live integration coverage, a regenerated catalogue, corrected project docs, 25 requirement IDs.

**Validation note:** the spec-less probe fallback was skipped for this phase (no SPEC.md). Truths
derive from the CONTEXT.md `<domain>` boundary, the live-integration mandate in its `<specifics>`
section, and 21-RESEARCH.md.

<interfaces>
From tests/integration/conftest.py:
  def assert_live_or_transient(data, tool, api=None) -> bool
      Returns True when live data is present so the caller can go on to assert on the payload.
      Returns False only after asserting the error code is genuinely transient — it tolerates
      UPSTREAM_ERROR, RATE_LIMITED and UPSTREAM_UNAVAILABLE, and nothing else.
      Assign to a plain local; the masking guard keys off conditionals over response-shaped names.
  def assert_rows(data, tool, *, allow_empty_reason=None) -> list
      Returns data["data"] as a list, asserting its type. Empty fails unless a reason is given.

MCP wiring (from .claude/rules/tests.md — the same wiring server main() does):
  from mcp_canada.server import mcp, _build_providers, _MODULES_DIR, _META_DIR
  from fastmcp import Client
  from fastmcp.server.providers import FileSystemProvider
  from fastmcp.server.transforms.search import BM25SearchTransform
  Tools are invoked as client.call_tool('call_tool', {'name': ..., 'arguments': {...}}).

<banned_idioms>
<!-- Enforced by tests/test_integration_test_quality.py in the DEFAULT unit suite. -->
A disjunction over the success and error shapes as a single assertion.
A conditional on the response shape whose body holds the only assertions.
An early return inside an error branch that abandons the remaining assertions.
A skip whose condition depends on the returned data.
To tolerate a genuine outage, assert the error code through assert_live_or_transient instead.
An exemption requires @pytest.mark.tolerates_upstream_error with a mandatory reason, capped at 10%
of the suite.
</banned_idioms>
