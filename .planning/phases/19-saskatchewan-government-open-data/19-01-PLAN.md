1. **Fix the shared `arcgis_hub.py:search_hub_datasets` pagination bug** (PREREQUISITE). Live-confirmed: `?offset=3` → `{numberMatched: null}` (silently broken); `?startindex=3` → correct pagination; `?startindex=0` → malformed body (must be omitted at 0). Manitoba Phase 18-09 worked around this per-module and explicitly deferred the shared fix; this plan does it properly. The fix is one param-name change plus updating the test that currently pins the bug, and re-running York/Alberta/Manitoba suites to confirm the fix repairs (not regresses) their latent live bug.

2. **Scaffold the `saskatchewan` module** (7-file pattern + test scaffolds with all stubs) and run the Wave 0 spike that resolves the two UNCERTAIN sources (WSA water-quality layer 19; Economy/Petroleum 400). This locks the contracts (constants, schemas, client signatures, fixtures) so Plans 02-05 fill bodies without colliding on file edits or chasing endpoint surprises.

This is the ArcGIS Hub pattern (Manitoba Phase 18 / Alberta Phase 17), NOT CKAN — Saskatchewan's machine-readable portal is `geohub.saskatchewan.ca` (ArcGIS Online org `zcv98lgAl8xQ04cW`), with a SECOND WSA org (`7MBdlVpjqbfBhQer`) and a SEPARATE SPSA REST server (`gis.saskatchewan.ca/egis`). `data.saskatchewan.ca` does NOT exist — never reference it.

Purpose: unblock the shared discovery path for all Hub modules and lock the Saskatchewan contract surface before any business logic.
