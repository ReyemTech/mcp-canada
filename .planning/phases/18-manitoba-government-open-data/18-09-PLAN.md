<objective>
Close the single major UAT gap from Phase 18: the 3 ArcGIS-Hub discovery tools
(`manitoba_search_datasets`, `manitoba_list_organizations`, `manitoba_list_categories`)
fail live with HTTP 400 because their client functions send ArcGIS-REST query params
(`num`/`start`, plus a blank `q=""`) to an OGC API Records (Hub Search v1) endpoint that
requires `limit`/`startindex` and rejects an empty `q`.

The root cause is fully diagnosed and live-confirmed in
`.planning/debug/manitoba-hub-search-400.md`. This is a pure request-parameter bug —
the host, path, item-detail endpoint, response flattening, and conftest fixtures are all
correct. The fix is surgical: change only the OUTGOING param names in 3 functions, keep the
public `num`/`start` tool signatures unchanged, and harden the tests that masked the bug.

Purpose: restore MB-01 (search), MB-04 (list organizations), MB-05 (list categories)
against the live API, and pin the corrected params so the regression cannot return.
Output: fixed `client.py`, param-regression unit tests, and a LIVE integration check.
</objective>
