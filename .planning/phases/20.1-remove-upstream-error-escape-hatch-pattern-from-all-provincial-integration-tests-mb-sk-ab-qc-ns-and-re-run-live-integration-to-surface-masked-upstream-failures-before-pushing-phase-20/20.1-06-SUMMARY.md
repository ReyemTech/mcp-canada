# Plan 20.1-06: PRESERVE audit, structured errors, phase close

## PRESERVE audit — 10 candidates down to 1 exemption

Most supposedly-tolerant tests did not need tolerance. Error-PATH tests (invalid
product, unknown station, unknown collection) were made two-armed; genuinely
empty-able results (Quebec road works, winter road conditions) state the reason
inline via `allow_empty_reason`; a nullable per-row field became `or ""`.

`test_store_pr_data_to_datastore` skipped when 2023 PR data was missing — which
is precisely how it hid the datastore dict-binding bug. Now asserts.

The NS AMI test mixed a zone-normalization PROOF with a sex-filter probe, so
whenever the filter matched nothing the proof silently did not run. Split; the
sex-filter half carries the **sole exemption** in the suite.

## Bug 9 — 16 tools with zero exception handling

The full live run surfaced 9 failures that pass in isolation: under load the
Health Canada Drug API times out, and neither drug_database nor nutrient_file
had a single `except`, so the timeout escaped as a raw ToolError instead of an
envelope. That breaks the project rule and defeats the hardened pattern — a test
cannot classify an exception it never receives. `upstream_guard()` applied to
all 16 tools.

## Close
