<objective>
Fix the IRCC multi-row merged header parsing blocker identified in UAT tests 5-7, 10, and 12.

Purpose: IRCC XLSX files use 3-5 merged header rows encoding a Year > Quarter > Month hierarchy. The current parser treats row 1 as a single header, producing 190 unnamed_* columns with garbage data. This blocks all data-returning IRCC tools.

Output: A new `_parse_ircc_xlsx()` function in parsers.py that uses openpyxl to forward-fill merged cells and build flat composite column names (e.g., "2015_q1_jan", "2015_total"). Per-dataset parse config in constants.py. Updated client.py to pass config through.
</objective>
