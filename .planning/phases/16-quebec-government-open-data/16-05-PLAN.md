<objective>
Close all 4 UAT gaps from phase 16 Quebec module by fixing three independent bugs and one BM25 keyword omission:

1. **Blocker (Gaps 1, 2 — silently also road_works + road_events):** `shared/parsers.py:fetch_and_parse` detects file format from URL path suffix only (line 513: `url.lower().split('?')[0]`). MTQ WFS endpoints put the format hint in the query string (`?outputformat=csv`), not the path. After stripping the query the path `/swtq` has no suffix and falls through to `_parse_xlsx`, which raises `zipfile.BadZipFile: File is not a zip file` on CSV bytes. Affects ALL 4 MTQ WFS tools: `fetch_bridge_structures` (UAT Test 8, surfaces UPSTREAM_ERROR), `fetch_road_conditions` (UAT Test 9, silently empty via try/except), `fetch_road_works` and `fetch_road_events` (silently broken, integration tests use tolerant `_meta or error` assertions).

2. **Major + doc-drift (Gap 2, Test 9):** `fetch_road_conditions` at `client.py:502-505` catches `Exception` and returns `[]`, masking the real BadZipFile. After Task 1 fixes the parser, the try/except becomes an active mask for future bugs and must be removed — let errors propagate to the tool layer which already wraps them as `UPSTREAM_ERROR`. Also: `16-RESEARCH.md:216` flagged `ms:conditions_routieres` as "LOW confidence" — live curl proved the endpoint returns 103KB of real CSV; the research doc is wrong and must be corrected.

3. **Major (Gap 3, Test 11 — different root cause):** The Hydro-Québec `historique-production-consommation` DQ package has ZERO CSV resources — all 4 are XLSX (years 2018-2021; 2020 has empty url=""). `fetch_electricity_data` at `client.py:754-757` hardcodes `(r.format or "").upper() == "CSV"`, so the matcher never hits, `csv_url` stays None, and the function returns `[]` before `fetch_and_parse` is ever called. Separately, `tools.py:614` hardcodes `api_url=BASE_URL + "package_show"` in the envelope, so even a successful fetch would report the wrong URL. Also: `16-RESEARCH.md:286` claims "CSV at Hydro-Québec direct URL" — the research didn't verify live; must be corrected to XLSX.

4. **Minor (Gap 4, Test 12):** `tools.py:291` Keywords line for `quebec_get_er_wait_times` lacks the literal tokens `health`, `medical`, `sante`. BM25 matches `"Quebec hospitals health"` 2/3 tokens versus 3/3 for `quebec_get_health_installations`. Trivial one-line fix.
