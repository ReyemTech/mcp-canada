# Plan 20.4-01: Invert the ValueError default

<objective>
Remove the defect behind four Codex findings across three PRs, rather than patch
a fifth instance of it.
</objective>

## The defect, stated once

| PR | Finding | Root cause |
|---|---|---|
| #2 | `json.JSONDecodeError` → `INVALID_INPUT` | subclasses `ValueError` |
| #3 | `pydantic.ValidationError` → `INVALID_INPUT` | subclasses `ValueError` |
| #4 | `UnicodeDecodeError` → `INVALID_INPUT` | subclasses `ValueError` |
| #3 | arbitrary exceptions escaped | httpx types enumerated, rest missed |

Three of four are the same sentence: *another `ValueError` subclass nobody
enumerated*. Each was fixed by adding one more arm above
`except ValueError -> INVALID_INPUT` — a deny-list against an open set.

## Tasks

- [x] **Structural test FIRST**, so it generates the worklist rather than

- [x] `shared/errors.py` — `InvalidInput` / `NotFound` / `UpstreamData`, all

## Order is load-bearing

The markers must be honoured by whatever catches them. york_region carries no
`@upstream_guard` (20.2 skipped its 28 tools because `_call_client` was already a
catch-all), so converting the raise without touching the handler silently did
nothing — which is exactly what Codex found.
