## Test 8 — MTQ Bridges WFS (ms:gsq_v_desc_strct_tri)

Live CSV header (after BOM strip):
  ide_strct, num_dossr, val_annee_, code_des_s, nom_route, nom_obstc, nom_muncp, cod_muncp,
  des_cs, code_des_t, nom_strct, rte_ind_pr, num_route, num_tronc, num_sectn, num_sr, num_rts,
  nbr_voie, val_chang_, val_chan00, cod_type_r, geo_coord_, geo_coor00, geo_lattd, geo_longt,
  geo_geomd_, val_longr, val_largr_, cod_type_s, cod_type00, cod_type_e, ind_strct_, ind_strc00,
  dirct_gen_, dirct_terr, dirct_te00

Key findings:
- Total features: 11,696. Default response without pagination: 30 rows.
- WFS 2.0 count+startIndex pagination: WORKS. count=500&startIndex=0 returns first 500.
- CQL_FILTER: SILENTLY IGNORED by this MapServer — filter is NOT applied server-side.
- num_route stores zero-padded 5-digit codes: '00020' = Autoroute 20, '00132' = Route 132.
- nom_route stores human names: 'Autoroute 20 Ouest', 'Autoroute 20 Est', 'Route 204'.
- Column names are already lowercase_snake — _normalize_key leaves them unchanged.
  'num_route' -> 'num_route', 'nom_muncp' -> 'nom_muncp' (bridge mapper is CORRECT).
- Autoroute 20 entries start at row index ~30 (not in default 30-row response).

WFS paging URL pattern:
  MTQ_BRIDGES_URL + &count=500&startIndex={offset}
  Loop until fewer rows returned than count.

Route normalizer mapping (user input -> num_route code):
  'A-20', 'Autoroute 20', 'autoroute 20', '20' -> '00020'
  'A-40', 'Autoroute 40', '40' -> '00040'
  General pattern: extract digits, zero-pad to 5 chars: '20' -> '00020', '132' -> '00132'
  Also match on nom_route ILIKE: 'Autoroute 20 Ouest' / 'Autoroute 20 Est' contain '20'

Recommended approach: normalizer converts user input to zero-padded 5-digit string, then
matches on num_route (exact) OR on nom_route (contains normalized digits substring).
Example: route='A-20' -> digits='20' -> zero_padded='00020'.
Match: r.get('num_route') == '00020' OR '20' in (r.get('nom_route') or '').
