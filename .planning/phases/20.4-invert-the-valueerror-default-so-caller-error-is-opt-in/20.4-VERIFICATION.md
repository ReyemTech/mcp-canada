## The defect, stated once

| PR | Finding | Why it happened |
|---|---|---|
| #2 | `json.JSONDecodeError` → `INVALID_INPUT` | subclasses `ValueError` |
| #3 | `pydantic.ValidationError` → `INVALID_INPUT` | subclasses `ValueError` |
| #4 | `UnicodeDecodeError` → `INVALID_INPUT` | subclasses `ValueError` |
| #3 | arbitrary exceptions escaped | httpx types enumerated, rest missed |

Three of four are the same sentence: *another `ValueError` subclass nobody
enumerated*. Each was fixed by adding one more arm above
`except ValueError -> INVALID_INPUT`. That is a deny-list against an open set —
`ValueError` is Python's generic bad-value base and any library may extend it.

## Codex review finding (PR #5) — valid, fixed

**york_region dropped `NotFound`.** Its tools carry no `@upstream_guard` —
Phase 20.2 skipped all 28 of them precisely because `_call_client` already had
a catch-all — so they never got the decorator that maps the markers centrally.
A `NotFound` raised for an unknown dataset id fell past `NoPortalError` and the
HTTP arms into `except Exception` and a routine missing record was reported as
an upstream outage. Marker arms now come first in `_call_client`.

Same root cause as the four preceding findings: the raise site was converted and
the handler that catches it was never walked.

**A note on the audit that followed.** Sweeping all three markers across every
tool reported **118** mishandlings. That number was wrong — the probe passed
junk arguments (`station="x"`), which trips each tool's own validation and
returns `INVALID_INPUT` before the mock is reached. Restricted to paths that can
actually occur, mishandlings are **zero**. Recorded because a bad measurement
that looks alarming is as dangerous as a missed defect.

## Note on the live-run timing

The full live run appeared to take 26 minutes, which briefly looked like the
Drug/Nutrient stall this project retired in Phase 20.3. It was not: pytest
self-reported **173.51s**. The wall-clock gap is best explained by concurrent
foreground `uv run` commands (pytest --cov, pyright, ruff) holding the uv
environment lock while the background run waited. Verified before amending the
20.1/20.3 reports again — the retirement of that caveat stands.

## Standing lesson

The three preceding phases each fixed a symptom in one place and generalised
without checking the neighbours. What broke the cycle was not more care; it was
a test asserting a *property* — "no unrecognised `ValueError` subclass may be
blamed on the caller" — rather than a list of known offenders. Prefer that shape
wherever code enumerates an open set: exception types, status codes, MIME types,
portal names. The question to ask is not "did I list them all?" but "what
happens when the list is wrong?"
