## Corrections made during verification

- **First count of 136 was wrong.** york_region's 28 tools delegate to a
  `_call_client` helper that already has `except Exception -> UPSTREAM_ERROR`.
  The detector now resolves module-level helper delegation, which removed all 28
  false positives. Caught by spot-checking a flagged tool rather than trusting
  the number.
- **The "obvious" one-line fix was rejected on evidence.** Adding the decode
  guard to `api_get` alone would have converted a mislabelled error into an
  unhandled one in the 5 modules catching only `HTTPStatusError`
  (`httpx.DecodingError` is an `HTTPError` but not an `HTTPStatusError`).
  Coverage had to land first.
- **Import rewrite bug caught before commit.** The transformer treated a trailing
  `# noqa` comment in `alberta/tools.py` as an import item, putting
  `upstream_guard` inside the comment. Caught by importing all 29 tool modules,
  not by reading the diff.

## Codex review findings (PR #3) — both valid, both fixed

- **P1: `upstream_guard` was not actually a catch-all.** It caught `httpx`
  errors, `JSONDecodeError` and `ValueError` only, so a `KeyError` from
  flattening code (a BoC observation missing `"d"`, a weather feature with no
  `"properties"`) still escaped as a raw `ToolError`. This was a hole in *this
  phase's own enforcement test*, which counts `@upstream_guard` as proof of
  coverage — the "108 tools covered" result was unearned for non-httpx failures.
  Fixed with a final `except Exception -> UPSTREAM_ERROR`, plus a test inside
  the enforcement module that proves the guard swallows an arbitrary exception
  type, so the assumption can never silently go false again.
- **P2: `pydantic.ValidationError` subclasses `ValueError`**, so an upstream
  payload failing model validation was reported as `INVALID_INPUT`. Same masking
  class as `JSONDecodeError`, one layer up. Now mapped to `UPSTREAM_ERROR` ahead
  of the `ValueError` arm; that arm is now reached only by an explicit
  `raise ValueError` for a genuinely bad argument.

Both were verified against the runtime before acting (`pydantic.ValidationError.__mro__`,
and the guard's actual `except` list), and both fixes were confirmed non-vacuous
by reverting `envelope.py` — all 6 new tests fail without it.

## Known limitation

`upstream_guard` reads `lang` from `kwargs`, so a tool invoked with `lang`
passed positionally falls back to `"en"` on the error envelope. Every call path
in this repo — MCP `call_tool`, the prompts, and the tests — passes it by
keyword, so no shipped path is affected.
