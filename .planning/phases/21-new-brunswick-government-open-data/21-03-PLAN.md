<objective>
The agent-facing guidance layer for New Brunswick: 6 prompts that chain the module's tools into
real workflows, and 7 resources that answer the questions an agent would otherwise burn a network
round-trip (or a wrong guess) on.

This module needs its documentation resources more than any prior province, because NB's portal
architecture is the most counter-intuitive one shipped so far: GeoNB is a **bare ArcGIS Server**
with no Hub Search API in front of it, its layer ids are non-guessable (Crown Land's only layer is
3; Wetlands is 2), several of its 62 services are retired or are tile indexes, its field names are
truncated shapefile artefacts (`Flood_Haza`, `Hospital_N`, `strID`), discovery for tabular data
lives on the **federal** catalogue rather than a provincial one, and 511 is key-gated. An agent that
guesses any of those gets a plausible-looking wrong answer.

This plan runs in parallel with 21-02: it touches only `prompts.py`, `resources.py` and
`test_prompts_resources.py`, none of which 21-02 modifies. It reads the tool manifest locked in
Wave 0 (after the discovery-surface checkpoint), so the tool names it references are already final.

Purpose: make NB's data reachable and its traps documented before an agent hits them.
Output: 6 prompts, 7 resources, and tests that pin their count, shape and tool-name validity.

**Validation note:** the spec-less probe fallback was skipped for this phase (no SPEC.md → no Edge
Coverage / Prohibitions to lift). Truths above derive from the CONTEXT.md `<domain>` boundary,
D-11/D-12 and 21-RESEARCH.md.
</objective>

<prompt_rules>
Guided workflow prompts return list[Message] with at least 2 messages: the first with the user role
asking what to analyse, the second with the assistant role giving numbered steps naming specific
tools and arguments. Quick lookup prompts return a plain str.
Every @prompt takes lang: Annotated[Literal["en","fr"], "Language: 'en' or 'fr'"] = "en".
Every @prompt uses the nb_ prefix.
</prompt_rules>

<resource_rules>
Every @resource takes ZERO function parameters. Any parameter — including lang — promotes the
function to a ResourceTemplate and removes it from resources/list. Bilingual content therefore goes
inline (both en and fr in the same payload), never behind a parameter.
data:// resources return json.dumps(...) — a valid JSON string, never a Python dict.
docs:// resources return a raw markdown string.
template:// resources return markdown carrying {placeholder} tokens for the agent to fill.
URIs are type-prefixed and module-prefixed: data://nb/..., docs://nb/..., template://nb/...
</resource_rules>
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → MCP prompt | Prompt arguments (`location`, `county`, `pid`, `query`) are interpolated into returned text |
| module → agent | Resource payloads are static, server-authored content returned verbatim |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-09 | Tampering | Prompt arguments echoed into workflow instructions an agent will act on | medium | mitigate | Prompt text instructs the agent to pass the value as a **tool argument**, never as a raw WHERE or fq fragment. The tools those instructions name build their filters server-side from typed parameters (T-21-01, T-21-04), so a hostile prompt argument cannot become an upstream query clause. |
| T-21-10 | Information Disclosure | `docs://nb/portal-guide` describes the 511 credential mechanism | low | mitigate | The guide names the environment variable and links the public 511 site; it never contains a key value and never instructs an agent to echo one back. |
| T-21-11 | Spoofing | Resource content is static and could drift from the live portal | low | accept | Static reference data (counties, health authorities, school sectors) is stable; the volatile parts (service list, layer ids) are regenerated from `21-SPIKE.md` and re-verified by the Plan 07 live integration suite. Drift is a documentation-accuracy risk, not a security one. |
| T-21-SC | Tampering | npm/pip/cargo installs | high | accept | Zero new packages — this plan writes only `json`- and markdown-producing functions on the existing stack. `git diff pyproject.toml uv.lock` stays empty. |
</threat_model>
