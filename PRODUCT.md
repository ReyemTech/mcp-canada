# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers installing mcp-canada in an MCP-compatible client, especially people who need to identify the right Canadian government data source and parameters without reading the entire repository.

## Product Purpose

mcp-canada gives AI agents structured access to Canadian federal, provincial, municipal, and local public data. The documentation must help a first-time visitor install it, discover an appropriate tool, and use that tool accurately.

## Positioning

One MCP server exposes a source-derived, bilingual catalog of Canadian public-data tools across jurisdictions and APIs.

## Operating Context

Users arrive from the repository or package installation, configure an MCP client, search for a data capability, and follow tool parameters and examples while working with an AI agent.

## Capabilities and Constraints

- Astro static site deployed through GitHub Pages.
- Tool metadata is generated from decorated Python source functions.
- Reference module pages must remain readable without JavaScript.
- English and French tool responses are a first-class capability.
- Documentation is factual and not a marketing funnel.

## Brand Commitments

The site may have more visual energy, but must remain calm, factual, and easy to scan. Footer attribution is limited to a compact link to Reyem Technologies.

## Evidence on Hand

- The live source-derived catalog contains 295 tools across 21 modules.
- `EXAMPLES.md` contains real cross-API workflows.
- No customer stories, performance benchmarks, or commercial proof should be invented.

## Product Principles

1. Get a developer from a question to the right tool with minimal friction.
2. Make the breadth of Canadian data feel navigable rather than overwhelming.
3. Treat bilingual support and source attribution as product features.
4. Preserve static, durable documentation over UI novelty.
