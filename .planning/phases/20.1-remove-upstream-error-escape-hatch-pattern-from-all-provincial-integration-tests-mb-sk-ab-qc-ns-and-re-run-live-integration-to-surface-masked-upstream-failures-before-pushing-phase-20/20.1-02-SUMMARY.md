# Plan 20.2-02: De-mask weather

De-masking immediately exposed **two real, shipped bugs** the guards had hidden.

## Bug 1 — every named-location weather lookup was broken

`wx_get_current_conditions(location="Toronto")` and
`wx_get_forecast(location="Vancouver")` both returned NOT_FOUND while lat/lon
worked. With only `location` given, bbox stayed None, so ogc_fetch pulled an
unordered first-50 page out of the 844-city citypage collection and filtered
THAT by name. Fixed with a server-side `name.{lang}` filter plus an exact-match
preference (`name.en=Toronto` returns "Toronto Island" first).

## Bug 2 — ahccd-trends used field names that do not exist

The collection uses bilingual double-underscore names
(`measurement_type__type_mesure`), not the SCREAMING_CASE of its sibling
collections. Every filtered call matched zero records and the flattener produced
all-None rows. The fixture carried the same invented keys, so the unit tests
agreed with the code rather than the API.

## Test-drift also found
- climate normals asked for a station that exists in climate-daily but not
  climate-normals (6158731 vs 6105976)
- climate trends asked for "temperature"; the collection is precipitation-only
- AQHI location_ids are opaque 5-letter codes, not "ON106"/"ON-01"
