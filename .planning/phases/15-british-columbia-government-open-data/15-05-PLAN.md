<objective>
Close all 5 UAT gaps from phase 15 British Columbia module by fixing two independent bugs:

1. **Blocker (Gaps 1, 2, 3, 5):** `british_columbia/client.py:_api_get` calls `.raise_for_status()` and `.json()` on the return value of `shared/http.py:api_get`, but shared `api_get` already returns parsed JSON (a dict, not an httpx.Response). The first live CKAN call raises `AttributeError: 'dict' object has no attribute 'raise_for_status'`, cascading into Tests 2, 3, 9, and 14 (7 integration failures). The 22 existing unit tests mask this because a `_make_http_response()` MagicMock helper patches the module-local `api_get` import with a fake Response wrapper — mirroring the buggy mental model instead of the real contract.

2. **Major (Gap 4):** `bc_get_water_wells` guard message at `tools.py:700-706` passes a hardcoded English literal to `make_error`. `make_error` only stamps `lang` into the envelope — it does NOT translate the message; the caller owns localisation. So `error.lang == "fr"` but `error.message` stays English, failing Test 13.

Purpose: Unblock the 4 CKAN-dependent tool call paths (`fetch_search_datasets`, `fetch_dataset_details`, `fetch_organizations`, `fetch_tags`, and `bc_query_features` via `fetch_dataset_details`) so the BC module works live; and make the single docstring-documented 130K guard honour its `lang` parameter.

Output:
- `_api_get` rewritten as a 6-line helper that treats `api_get` result as a dict, checks `envelope.get("success")` directly, returns `envelope.get("result", {})`.
- Existing `_make_http_response` MagicMock helper replaced with an `AsyncMock` pattern that returns raw dicts (matching the real contract).
- New contract unit test patching `mcp_canada.shared.http.api_get` (not the module-local import) to prove the real shared contract is exercised.
- `bc_get_water_wells` guard message wrapped in an inline `lang == "en"` ternary with French translation.
- New regression test asserting French guard message contains `"au moins un"` when `lang="fr"`.
- All existing BC unit tests stay green; BC integration tests go from 7 failed to 0 failed; `bc_get_water_wells(lang="fr")` with no filters returns a French error message.

Scope boundaries (explicit non-goals):
- Do NOT modify `src/mcp_canada/shared/http.py:api_get` — 5 other modules (open_parliament, weather/collections, weather/climate, etc.) already rely on the parsed-JSON contract and would break.
- Do NOT introduce `shared/i18n.py:t()` for the one-off guard message — `t()` currently has zero production imports and expanding its surface area for a single message is scope creep. The inline ternary matches the established convention used in 7+ modules' `prompts.py` files.
- Do NOT audit the ~29 other `make_error` call sites in `bc/tools.py` for bilingual coverage — the project-wide hardcoded-English pattern is systemic and belongs in a future dedicated bilingual-errors phase.
- Do NOT update `README.md` or `CLAUDE.md` — both fixes are internal bug fixes with zero user-facing API surface changes.

    ```python
    async def _api_get(path: str, params: dict[str, Any] | None = None) -> dict[str, Any]:
        """Fetch from BC Data Catalogue CKAN API and unwrap the CKAN success envelope.

        shared/http.py:api_get already returns parsed JSON (dict) — never a Response.
        HTTP-level errors (4xx/5xx) are raised inside shared api_get's internal _fetch().
        This helper only checks CKAN's application-level `success: false` envelope.

        Args:
            path: Action API path (e.g. "package_search") relative to BASE_URL.
            params: Optional query parameters.

        Returns:
            The unwrapped CKAN result field (dict or list wrapped in a dict).
        """
        url = BASE_URL + path
        envelope = await api_get(url, params or {})
        if not isinstance(envelope, dict) or not envelope.get("success", False):
            raise httpx.HTTPStatusError(
                f"CKAN returned success=False for {path}",
                request=httpx.Request("GET", url),
                response=httpx.Response(500),
            )
        return envelope.get("result", {})
    ```
